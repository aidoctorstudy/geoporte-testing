# i18n — nav language switcher

Restores ADR-0024's design (reversed by ADR-0077, restored by ADR-0088/0089)
with one change forced by reality: the official hosted LibreTranslate API
now requires a paid API key, so this implementation tries LibreTranslate
only when self-hosted/keyed, and falls back to MyMemory (free, keyless,
confirmed reachable) otherwise. See ADR-0089 for the full reasoning.

## Scope — nav links, section headings, button labels only

Not full body copy. This project went English-only once already (ADR-0077)
after shipping the wider ADR-0065 scope; restoring the original, narrower
ADR-0024 boundary is a deliberate choice, not an oversight. If you need a
new string translated, ask: is this nav chrome, a section heading, or a
primary CTA button? If it's body copy (a paragraph, a bio, a card
description), it's out of scope — leave it as a literal string.

## Languages

`src/lib/i18n/languages.ts` — English, Arabic, Urdu, French, Chinese.
Arabic/Urdu are `dir: "rtl"`; the other three are `dir: "ltr"`.

## Pieces

| Piece | File | Role |
|---|---|---|
| Language list | `src/lib/i18n/languages.ts` | Codes, native labels, `dir` |
| Persisted choice | `src/hooks/i18n/use-language-store.ts` | `zustand` store, manual `localStorage` load/save (mirrors `cookieStore.ts`'s shape, not `zustand/persist` — see below) |
| Batching | `src/lib/i18n/translation-queue.ts` | Coalesces every `useTranslated` call in one tick into one `/api/translate` request per language |
| Hook | `src/hooks/i18n/use-translated.ts` | `useTranslated(text)` — cache hit resolves sync; a miss queues and re-renders on resolve |
| Leaf component | `src/components/common/TranslatedText.tsx` | `<TranslatedText text="…" tag="span" />` — for plain JSX children |
| `<html>` sync | `src/components/common/LanguageDirection.tsx` | Hydrates the store on mount; keeps `lang`/`dir` on `<html>` in sync |
| Switcher UI | `src/components/common/Nav/LanguageSwitcher.tsx` | Desktop nav dropdown (same hover+tap pattern as `ServicesDropdown`) |
| Mobile switcher | Inline in `src/components/common/Nav/MobileMenu.tsx` | A row of language buttons, not a dropdown — a full-screen menu doesn't need one |
| Server proxy | `src/app/api/translate/route.ts` | The only thing allowed to call a third-party translation API (hard rule #9) |

### Why a manual store, not `zustand/persist`

`cookieStore.ts` already established this project's pattern: read
`localStorage` in an explicit `hydrate()` action called from a mounted
leaf's `useEffect`, gated by a `hydrated` boolean — never read it at store
*creation* time. `zustand/persist`'s default behaviour rehydrates
synchronously during module init on the client, which runs before
hydration completes and can disagree with the server-rendered `<html
lang="en">` — the exact class of hydration-mismatch bug ADR-0087 fixed
elsewhere in this project. `use-language-store.ts` copies `cookieStore.ts`'s
shape instead of reaching for the middleware.

### Where translation must resolve before it reaches the child

`TextEngine` (`spring-text-engine`) and some other components read
`children` directly rather than rendering nested components first — the
same constraint `<TranslatedText>` can't satisfy for an eyebrow/heading.
`SectionHeading.tsx`, `HeroHeading.tsx`/`HeroSubtext`, and
`GeotechnicalPlexusHeading.tsx` all call `useTranslated()` directly and
pass the resolved plain string in, rather than wrapping in
`<TranslatedText>`. `AboutHeading.tsx`'s lines go through `<Inview>`
instead, which renders arbitrary children fine, so they use
`<TranslatedText>` directly.

### Where it's wired

Centralizing headings into a handful of shared components (above) means
wiring translation into *those* covers every section heading sitewide for
free — no need to touch every section file individually. Nav links/CTA
buttons are more scattered; every `<Magnetic>`-wrapped CTA (this project's
own convention for marking a primary call-to-action) got
`<TranslatedText>`: `Nav.tsx`, `HeroSection.tsx`, `GeotechnicalPlexusSection.tsx`,
`ServiceCta.tsx`, `GeotechnicalAnalysisHero.tsx`. Nav chrome: `Nav.tsx`,
`MobileMenu.tsx`, `ServicesDropdown.tsx`'s "Services" trigger, and
`Footer.tsx`'s nav links + CTA (the footer repeats the primary nav, so it's
chrome too — see `nav-links.ts`). Dynamic/data-driven strings (a service's
`title`, a project's description, a team member's bio) are deliberately
**not** wired — they're body/data content, out of this scope.

## Translation providers (`/api/translate`)

1. **LibreTranslate**, only when `LIBRETRANSLATE_ENDPOINT` is set (a
   self-hosted instance, or the official API with `LIBRETRANSLATE_API_KEY`
   — confirmed live that an unauthenticated call to libretranslate.com now
   returns `{"error":"Visit https://portal.libretranslate.com to get an
   API key"}`, so this is never usable unconfigured).
2. **MyMemory** (`api.mymemory.translated.net`) — free, keyless, confirmed
   reachable for en→ar/ur/fr/zh from this deploy target. Used whenever
   LibreTranslate isn't configured or a request to it fails.

Both are tried server-side only, per string, with a 5s timeout each; a
string that fails both resolves to its own English source — never an
error surfaced to the browser. MyMemory's top-level `translatedText` is
occasionally a bracketed translator's note rather than a real translation
for short/rare strings; the route filters those out in favour of the
best-scored plain entry in its `matches` array.

Two public LibreTranslate mirrors were checked and ruled out at the same
time: `translate.argosopentech.com` no longer resolves (DNS), and
`lingva.ml` sits behind a Cloudflare bot challenge that blocks
server-to-server calls outright.

## RTL — what `dir="rtl"` actually covers

`LanguageDirection.tsx` sets `document.documentElement.dir = "rtl"` for
Arabic/Urdu. This is the correct, standard signal for bidi text handling,
default text alignment, and native UI mirroring (form controls,
scrollbars) — and is exactly what the original (pre-ADR-0077) system did.

**It does not auto-mirror every physical-direction Tailwind utility.**
Classes like `pl-4`, `right-0`, `-translate-x-1/2` don't flip under
`dir="rtl"` — only CSS logical properties (`ms-`/`me-`/`ps-`/`pe-`,
`text-align: start`) do, and this codebase's components are written with
physical utilities throughout (confirmed by grep: `left-`/`right-`/`pl-`/
`pr-` are the norm, e.g. `ServicesDropdown.tsx`, `CookieBanner.tsx`). A
true full-layout RTL mirror would mean auditing and converting every such
utility sitewide to its logical equivalent — a much larger, separate pass
that was not part of this change and wasn't part of the original
pre-ADR-0077 system either, as far as the historical ADRs describe. Noted
here rather than silently overclaimed.

## When building

`useTranslated(text)` for a plain string inside a component that already
has other hooks; `<TranslatedText text="…" tag="…" />` for a leaf JSX
usage. Both read `useLanguageStore`, so neither needs a language prop
threaded through. On upstream failure, the string simply stays untranslated
— no error state to design for.
